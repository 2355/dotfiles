$ARGUMENTS を元に Notion チケットから spec ファイルを作成してください。

## 引数の解析

- 第1引数: Notion チケットの URL（必須）
- 第2引数: spec ファイルの出力先パス（任意）
  - 指定がない場合は `.claude/<チケット番号>/spec.md` に出力する
  - チケット番号は Notion ページのプロパティから取得する（ID やチケット番号に相当するもの）
  - チケット番号が取得できない場合はページタイトルを kebab-case に変換してディレクトリ名とする

## 手順

1. Notion チケットの内容を取得する
   - `mcp__plugin_notion-mcp_notion__notion-fetch` ツールで Notion ページの内容を取得する
   - ページタイトル、プロパティ（ステータス、担当者、期限など）、本文をすべて読み取る

2. チケットの内容を分析する
   - 取得した情報から、以下の項目を整理する
     - 何が求められているか
     - 前提条件や制約はあるか
     - 関連するコードやファイルへの言及はあるか
   - **推測で補完しない**。チケットに書かれていない情報は「不明」として扱う

3. 不明点があればユーザに質問する
   - 以下のような情報がチケットから読み取れない場合、spec 作成前にユーザに確認する
     - 対象のリポジトリやディレクトリが不明
     - 要件が曖昧で複数の解釈ができる
     - 受け入れ条件が明示されていない
     - 技術的な制約や方針が不明
   - 質問はまとめて1回で行い、回答を得てから次に進む

4. spec ファイルを作成する
   - 以下のフォーマットで spec ファイルを出力する
   - 各セクションにはチケットから読み取れた事実のみを記載する
   - コードベースの調査が必要な場合は、調査した結果を記載する

5. 作成した spec ファイルの内容をユーザに提示し、過不足がないか確認する

## spec ファイルのフォーマット

```markdown
# <チケットタイトル>

- チケット: <Notion URL>
- 作成日: <spec 作成日>

## 背景

<!-- なぜこのチケットが必要なのか。現状の課題や動機を記載する -->

## ゴール

<!-- この対応で達成したいことを簡潔に記載する -->

## 要件

<!-- 具体的な要件をリストで記載する -->

- [ ] 要件1
- [ ] 要件2
- [ ] 要件3

## 受け入れ条件

<!-- この対応が「完了」と言える条件をリストで記載する -->

- [ ] 条件1
- [ ] 条件2

## 技術的な補足

<!-- 対象ファイル、影響範囲、既存の実装に関する調査結果など -->

## 未解決の疑問点

<!-- spec 作成時点で解消できなかった疑問があれば記載する -->
```

## 注意事項

- チケットに書かれていない情報を推測で埋めない
- コードベースの調査は必要に応じて行い、結果を「技術的な補足」に記載する
- spec ファイルの要件・受け入れ条件はチェックボックス形式にする（実装時に進捗管理できるようにするため）
