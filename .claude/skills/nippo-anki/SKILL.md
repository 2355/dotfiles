name: nippo-anki
description: 日報（~/work/nippo/YYYY-MM-DD.md）の「💡 学びと気づき」のうち、まだ Anki に取り込んでいないものを選別して Q&A カードにし、ユーザの確認を経て AnkiConnect で分野別デッキに登録する。「学びを anki に登録して」「日報の学びを Anki に入れて」「anki に追加して」「暗記カードにして」などと言われた場合にこのスキルを使用する。
---

日報の学びを、間隔反復で定着させるための Anki カードにする。

```
pending（未処理の学びを抽出）→ 選別・Q&A 化 → ユーザ確認 → register（登録 + 処理済みに記録）
```

- 補助スクリプト: `${CLAUDE_SKILL_DIR}/scripts/nippo-anki.mjs`
- 作業ファイルはスクラッチパッドに置く。以下、スクラッチパッドのパスを `$W` と表記する（シェル変数ではないので、実パスに置き換えて実行する）
- 処理済みかどうかは学び 1 件ごとのハッシュで判定し、`~/.local/state/nippo-anki/processed.json` に記録される。日付で区切らないので、書きかけの日報を処理したあとに追記された学びも次回拾える
- 日報の場所は既定で `~/work/nippo`。環境変数 `NIPPO_DIR` で変えられる
- ノートタイプは `基本` / `Basic` を自動で探す。どちらも無い言語の Anki では、環境変数 `NIPPO_ANKI_MODEL` で表面・裏面を持つノートタイプ名を指定する
- state ファイルが消えた場合は、全学びが未処理に戻る。Anki に登録済みの最終日（`tag:nippo::YYYY-MM-DD` の最大）をユーザに確認し、`nippo-anki.mjs seed <その日付>` で作り直す

## 1. Anki の起動を確認し、未処理の学びを抽出する

```bash
curl -s -m 3 localhost:8765 -X POST -d '{"action":"version","version":6}'
node ${CLAUDE_SKILL_DIR}/scripts/nippo-anki.mjs pending $W/pending.json
node ${CLAUDE_SKILL_DIR}/scripts/nippo-anki.mjs decks
```

- 応答がなければ、Anki.app を起動するようユーザに頼む（AnkiConnect は Anki の起動中だけ動く）
- `pending=0` なら、登録するものがないと伝えて終わる
- `$W/pending.json` は `{id, date, text, hash, dateHasProcessed}` の配列。全件読む
- `decks` は日報のカードを入れてよいデッキの一覧（`nippo` タグのカードが入っているデッキ）。手順 2 のデッキ選びに使う
- `dateHasProcessed: true` の学びは、処理済みの学びを後から直したか、同じ日に追記したものの可能性がある。`findNotes`（クエリ `tag:nippo::<date>`）で既存ノートの id を取り、`notesInfo` で中身を読む。同じ論点のカードが既にあれば外す（外したもの一覧に「登録済み」と書く）。問いの文言が変わると Anki 側の重複判定では防げないため

## 2. 選別して Q&A 化する

目的は、職場やプロジェクトが変わっても役立つ一般的な知識を定着させること。

### 残すもの・外すもの

| 残す | 外す |
|---|---|
| 言語・ライブラリ・外部サービスの仕様や挙動 | 特定のリポジトリ・プロジェクト・組織でしか通用しない知識（業務ルール、システム構成、運用手順、特定のテーブルや関数の経緯など） |
| 設計・テストの原則 | その日限りの状況メモ・進捗 |
| 再発しうる落とし穴とその対処 | 要調査・未起票などの ToDo |
| Claude Code などツールの使い方の知見 | 「〜かもしれない」程度の曖昧な所感、問いにならない薄い内容 |
| 仕事の進め方の教訓 | 他の学びとほぼ重複するもの（情報量の多い方を残す） |

- 業務の中で得た学びでも、主題が言語や外部サービスの仕様なら一般的な知識として残す。固有かどうかは「そのプロジェクトを離れても通用するか」で判断する
- 迷うもの（原文に「未検証」とある、状況メモに近いなど）は残し、`unsure` に理由を書く。登録時に `要確認` タグが付き、復習中に判断できる
- ただし固有の知識かどうかで迷うものは、残さずに外す（外したもの一覧に理由を書き、ユーザが確認時に戻せるようにする）。固有の知識を入れないことのほうが `unsure` より優先する

### カードの作り方

- question: 答えを思い出させる具体的な問い。1 枚 1 論点。学びに論点が複数あれば複数カードに分ける
- answer: 要点を 1〜3 文で。原文にある具体例（PR 番号、ファイル名など）は「例:」として残してよい。他の言語との比較が原文にあれば残す
- 原文にない事実を足さない。推測で補完しない（カードは今後何度も見返すので、誤りが混じると誤りを覚えてしまう）
- コード識別子は `バッククォート` のまま書く（登録時に `<code>` に変換される）
- deck: 手順 1 の `decks` の一覧から 1 つ選ぶ
  - どれにも合わないときだけ新しいデッキ名を考え、そのデッキのカードに `"newDeck": true` を付ける。新しいデッキは分野ごとにトップレベルに置く（`::` で階層を作らない）。既存のデッキには付けない
  - 初回など一覧が空のときは、全カードが新しいデッキになる。言語・フレームワーク・外部サービス・設計・テスト・ツールなど、分野ごとに 1 デッキを目安にする
  - スクリプトは、一覧に無いデッキのうち `newDeck` が付いていないものを拒否する。選別のたびに分類がぶれてデッキが増えていくのを防ぐため

結果を `$W/cards.json` に書く:

```json
[{"deck": "Go", "question": "...", "answer": "...", "date": "2026-11-24", "unsure": "原文に未検証とある", "newDeck": true}]
```

`unsure` は迷ったときだけ、`newDeck` は新しいデッキを提案するときだけ付ける。`date` は元の学びの日付。

pending が 50 件を超える場合は、pending を分割してサブエージェントに並列で任せ、この節の基準を渡す。統合時に、pending の全 id に判定（残す・外す）があることを確かめてから次に進む。

## 3. ユーザに確認する

候補を番号付きの一覧で示す。外した学びも 1 行ずつ理由を添えて示す（選別が妥当かをユーザが確かめられるように）。新しいデッキがあれば冒頭にまとめて示し、作ってよいかの承認を得る。

```
## 新しいデッキ（承認が必要）
- Kotlin（3 枚）

## 登録候補（N 枚）
1. [Go] 問い
   → 答え（出典日）
2. ⚠️ [Stripe] 問い …   ← unsure 付き
3. 🆕 [Kotlin] 問い …    ← newDeck 付き（新しいデッキ）

## 外したもの（M 件）
- 2026-11-24「〜」: プロジェクト固有
```

ユーザの指示を反映する。register は pending.json の全件を処理済みにするので、「次回に回す」ものは pending.json 側から消す必要がある。

| ユーザの指示 | 反映先 |
|---|---|
| カードを外す | cards.json から消す（元の学びは処理済みになり、次回は出ない） |
| 問い・答え・デッキを直す | cards.json を直す。直した先が `decks` の一覧に無いデッキなら、`newDeck: true` を付ける |
| 新しいデッキを却下する | そのカードを一覧にあるデッキに振り直し、`newDeck` を外す |
| 外した学びを残す | cards.json にカードを足す |
| この学びは次回に回す | その学びのカードを cards.json から消し、学びを pending.json から消す |
| 今回は登録しない | register を実行せずに終える（何も処理済みにならない） |

## 4. 登録する

```bash
node ${CLAUDE_SKILL_DIR}/scripts/nippo-anki.mjs register $W/cards.json $W/pending.json
```

- 登録に成功すると、pending の全件（外した学びも含む）が処理済みとして記録される
- 失敗した場合（Anki 未起動、承認されていないデッキ、重複以外の理由で登録できないカードなど）は、何も処理済みにしない。今回作った空のデッキも消える。エラーの原因を直して再実行する
- デッキ名の大文字小文字が既存のデッキと違うだけなら、既存の表記に揃えて登録される
- 同じ問いがデッキに既にあれば、Anki 側で重複とみなして飛ばされる（出力の `skippedDuplicate`）。判定は問いの完全一致だけなので、文言が違う同じ論点のカードは防げない

出力をもとに、登録枚数をデッキ別の表で報告する。`要確認` タグのカードがあれば、Anki の検索で `tag:要確認` と入れると絞り込めることも伝える。
