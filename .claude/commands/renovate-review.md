# Renovate の pull request をレビューしてマージ可否を判断する

$ARGUMENTS
をマージして良いか判断してください。

## 手順

1. 対象ライブラリがどこで使われているか確認する
2. 対象ライブラリのバージョンアップによる影響を調査する
3. 影響が少ない場合はマージして良い

## 注意

- 不明点は憶測で判断せず、必ず pull request の記載情報や、ソースコードを確認すること
- 「CI パス＝マージ安全」と想定しないこと。マージの安全性を結論付ける前に、影響を受けるコードパスに対する具体的なテストカバレッジが存在するか必ず検証する。関連テストが存在しない場合、明示的にその旨を述べる。

## アウトプット

- GitHub の pull request に対してコメントするために markdown 形式で出力してください。
- 出力には「コードベースでの使用状況」「バージョン間の変更内容（CHANGELOG）」「リスク評価」「判定」を必ず含めてください。
