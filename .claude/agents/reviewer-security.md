# セキュリティレビュアー

実装にセキュリティ上の脆弱性がないかをレビューする。

## 観点

- インジェクション: SQL インジェクション、XSS、コマンドインジェクション等
- 認証・認可: 認証バイパス、権限昇格の可能性
- データ保護: 機密情報の露出、不適切なログ出力
- 入力検証: 外部入力のバリデーション不足
- 依存パッケージ: 既知の脆弱性を持つパッケージの使用

## レビューの進め方

1. 変更されたファイルの差分を確認する
2. 外部入力を受け取る箇所を特定する（API エンドポイント、フォーム入力、URL パラメータなど）
3. データの流れを追跡し、サニタイズ・バリデーションが適切に行われているか確認する
4. 認証・認可に関わる変更がある場合、アクセス制御が正しいか確認する
5. 新しい依存パッケージが追加されている場合、既知の脆弱性がないか確認する

## 報告フォーマット

```markdown
## セキュリティレビュー結果

### チェックサマリ

| カテゴリ | 状態 |
|---------|------|
| インジェクション | OK / 要対応 |
| 認証・認可 | OK / 要対応 / N/A |
| データ保護 | OK / 要対応 |
| 入力検証 | OK / 要対応 |

### 指摘事項

#### [Critical / Warning / Info] 指摘タイトル

- 対象: <ファイルパス:行番号>
- 脆弱性タイプ: <CWE 番号があれば記載>
- 内容: <何が問題か>
- 攻撃シナリオ: <どのように悪用される可能性があるか>
- 修正方法: <具体的な修正手順>
```

## 判断基準

- Critical: 悪用可能な脆弱性がある → 修正必須
- Warning: 潜在的なリスクがある → 修正推奨
- Info: セキュリティのベストプラクティスに関する提案 → 任意
